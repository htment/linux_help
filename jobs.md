1. Первая задача ([1]):
bash
```
nohup sudo rsync -avh --progress /mnt/upload/SORT_files/ /PHOTO_VIDEO/SORT_files/ 2>&1 > RSYNC05.07.2025 &
```
Что делает?
Копирует файлы из /mnt/upload/SORT_files/ в /PHOTO_VIDEO/SORT_files/ с прогрессом (--progress).

Особенности:

``nohup`` — позволяет процессу работать даже после закрытия терминала.

``2>&1 > RSYNC05.07.2025`` — перенаправляет вывод (включая ошибки) в файл RSYNC05.07.2025.

``& ``— запускает процесс в фоне.

2. Вторая задача ([2]):
bash
```
nohup sudo rsync -avh --remove-source-files --progress /mnt/*-* /mnt/UNSORT/ 2>&1 > RSYNC05.07.2025_2 &
```
Что делает?
Копирует файлы из /mnt/, имена которых содержат дефис (*-*), в /mnt/UNSORT/, удаляя исходные файлы после копирования (--remove-source-files).

Особенности:
```
--remove-source-files — удаляет исходные файлы только после успешного копирования (не путать с --delete, который удаляет лишние файлы в назначении).
```
Вывод также записывается в RSYNC05.07.2025_2.


Как управлять этими задачами?
Вывести список фоновых задач:

bash
```
jobs
```
Вернуть задачу на передний план:

bash
```
fg %1    # для задачи [1]
fg %2    # для задачи [2]
```
Приостановить/возобновить:

Нажать ``Ctrl + Z``(если задача на переднем плане), затем:

bash
``
bg %1   # продолжить в фоне
``
Завершить задачу:

bash
```
kill %1   # для задачи [1]
kill %2   # для задачи [2]
```
Почему файлы не копируются?
Если в предыдущем выводе rsync показывал total size is 0, возможные причины:

В `` /mnt/upload/SORT_files/ нет файлов (проверьте ls /mnt/upload/SORT_files/).``

Нет прав на чтение (даже с sudo).

Файлы уже скопированы, и rsync их пропускает (попробуйте rsync -avh --ignore-existing).

Если нужно проверить текущий статус копирования, смотрите логи:

bash
``
cat RSYNC05.07.2025
cat RSYNC05.07.2025_2
``
Используйте ``disown``: После запуска команды nohup rsync ... &, добавьте команду ``disown %1``. Это отсоединит процесс от вашей текущей сессии shell, что сделает его неуязвимым для сигналов Ctrl+C от вашей сессии.
